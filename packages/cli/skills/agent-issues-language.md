# Language standard

When reporting information to me, be extremely concise and sacrifice grammar for sake of concision.

Use simple, direct language in every interaction with the user, including questions, progress updates, explanations, and final responses. Write tracker records, plans, prompts, handoffs, and final reports the same way. Prefer short sentences, familiar words, and concrete descriptions of behavior. Use established project terms and precise technical language when they clarify meaning; do not add jargon, ceremony, or abstraction for its own sake.

Lead with the answer, decision, or action. Give supporting detail only when it changes what the user should do or understand. Do not repeat the user's request or restate unchanged plans. Use short lists when they improve scanning. State assumptions, uncertainty, risks, and tradeoffs plainly, but do not pad responses with routine caveats. Match the level of detail to the task: concise by default, fuller when the decision is complex or the user asks for depth.
